How it works

Template, slots, contents.

A site is one source on S3 with its templates, contents, assets and pages. A page holds copies of what it shows, so a change reaches a page only when the operator asks for it.

01

One layout, many pages

A template is Python build code with slots. Every page uses a copy of it and fills its slots with contents, written in HTML or Markdown in the block editor.

02

Copies you update on purpose

Editing a content changes the original. The Update plan lists the pages holding a copy, selects the ones not changed by hand, and brings them up to date.

03

Versions on S3

Every save of the site is an S3 version of its source; every publication of a page is an S3 version of its object. Restore a source or put an earlier page online.

One set of operations

For editors, scripts and LLMs.

The administration, REST with OpenAPI, MCP and Help me use the same site operations. Help me is a Sonnet chat beside the editor: it asks what the site is for, offers palettes and logo sketches, and builds the pages.

Every change carries an idempotency key: a retry with the same key returns the first result. Publishing stays a command of the operator.

Publication

From a working copy to a public site.

Each step is an explicit command. Nothing becomes public as a side effect of saving.

Edit and save

The site tab works on the editor's working copy; site_save writes it as a new version of the source.

Check

publish_plan lists every page in every language as new, changed or unchanged, with its SEO warnings.

Publish

publish renders the selected pages, writes one object per page and language, then the site index that pins them.

Serve

A Kajenn site server reads the index and the site's address from the release bucket and serves the pages, sitemap and redirects.

Roll back

page_rollback puts an earlier version of a page online; site_rollback restores a saved source and republishes.
