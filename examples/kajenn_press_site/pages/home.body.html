How it works

Content, release, rollback.

Kajenn Press separates three things: the identity of a piece of content, its editorial revisions, and the releases that put it online.

01

Content with history

Every page, template and resource has a stable identity. Each save creates an immutable revision. Each language has its own draft, and concurrent edits are detected through the record generation.

02

A publication is a release

A build renders a coherent set of pages and resources into a complete release. Activating it changes a single channel pointer, so the site never shows half of a change.

03

Rollback without rebuilding

Rollback reactivates a release that was already published. It does not run Gramlot or HtmlBuilder again: the bytes that were online come back unchanged.

One set of services

For editors, scripts and LLMs.

The same operations are exposed through REST with OpenAPI and through MCP. An authorized LLM can create a site, write templates and content, read diagnostics, check a preview and publish.

Every mutation carries an idempotency key. Updates carry the expected generation of the record. A retry with the same key returns the original result instead of creating more history.

The publication cycle

From a draft to a public site.

Each step is an explicit operation. Nothing becomes public as a side effect of saving or building.

Save a draft

draft_save stores the named blocks of a page against an exact template revision.

Build a candidate

candidate_create fixes the exact revisions to publish. build_start renders them in a separate worker process.

Preview it privately

preview_grant_create issues a time-limited preview link. preview_grant_revoke withdraws it.

Activate the release

release_activate makes the build public, on the condition that the channel has not changed in the meantime.

Roll back

release_rollback reactivates a previous release of the same channel.
