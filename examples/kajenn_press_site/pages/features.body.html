Editing

A model for editorial work.

01

Sites and languages

One installation manages several sites. Each site declares its languages, and each language of a page is a separate variant that is published when it is ready.

02

Exact revisions

Sources are stored as exact bytes. Every change creates an immutable revision, and any past revision can be read, compared or restored.

03

Shared resources

Templates, CSS, JavaScript and media belong to one site or to the shared library. A template declares the exact resource revisions it depends on.

Rendering

Templates in Python, pages in static HTML.

A trusted template defines build(source, data) with Gramlot or HtmlBuilder. Editors fill named HTML or Markdown blocks. The build produces complete HTML that works with JavaScript disabled.

The data a template receives

  • site.id, site.name and language
  • page.id, page.variant_id and page.title
  • blocks.<name> with the prepared editorial HTML
  • resources.<revision>.url and kind
Editorial HTML and Markdown pass through the same nh3 allowlist. Scripts, event handlers, iframes and unsafe URL protocols are removed, and the diagnostics name the block that was filtered.

Building and publishing

Every step is explicit.

04

Persistent builds

A candidate fixes the exact revisions to publish. The build runs in the background in a separate Python process, with an isolated interpreter, a timeout and an output limit.

05

Private previews

A preview grant issues a link that expires and can be revoked. Previews are served from their own origin and never change a public channel.

06

Activation and rollback

Activation and rollback are conditional on the channel generation. Rollback reactivates a published release without running the template engines again.

Storage and serving

No database required.

The catalog lives on a local filesystem. Payloads, media and manifests live in Genro Storage. Asqueel on PostgreSQL is a planned alternative backend.

Crash-safe commits

All changes of a command succeed or fail together. Receipts and a recovery report tell committed operations apart from incomplete ones.

Release storage

After each activation or rollback, the active release is exported to a Genro Storage mount: a local volume or an S3 bucket.

Serving without the catalog

A StaticSiteServerApplication child serves the public pages directly from release storage.

Status

Version 0.1.0.

The editorial backend, rendering, builds, previews, publication and release storage are implemented. The multisite Gramlot administration is in its first phase. The HTML, Markdown, CSS and JavaScript editors come next.
