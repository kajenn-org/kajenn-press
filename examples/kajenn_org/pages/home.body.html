Design principles

Predictable by construction.

kajenn is a spec-first redesign. Three principles govern almost every API decision.

01

No globals

State lives in instances. A server is an object you build; components reach each other through an explicit parent reference. A test can start a fresh isolated server on every run.

02

Config is data

You describe what you want with plain data and hand it to objects that already exist. Switching a backend changes the data, not the structure of your code.

03

Objects always exist

Sessions, authentication and tasks are always present. Configuration decides which backend they use, so there is no "is it enabled?" branching.

One rule for every server

The demux rule.

An application has a code, its name, and a mount, the URL prefix it answers under. Every request is dispatched the same way.

First path segment → the application mounted there, if one is; else the application on the site root, if there is one; else, for / itself with a default declared, a 307 to that application's mount; else 404.

A server with one application on the root is a usage of this rule, not a different mechanism. Read the model →

One route tree, several transports

REST, OpenAPI and MCP from the same handlers.

Routing is delegated to genro-routes, a protocol-neutral routing library. The route tree does not know whether it is called over REST, OpenAPI or MCP, so the same tree can be exposed through several transports. The management surface lives in the _server application, mounted on every server.
