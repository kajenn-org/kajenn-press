## Objective

Deliver the first usable filesystem/Genro Storage foundation of kajenn-public-site: durable local catalog operations followed by authenticated REST/MCP management of sites, multilingual drafts, source resources and generic-resource copies. The result is inspectable and runnable without a database; it is the input to the rendering/publication macro in the [roadmap](../../roadmap.md).

This plan authorizes implementation only when `/execute-phase` is invoked. Planning itself creates no application code, installs no dependencies and changes no sibling repository. Phases execute serially and are reviewed in this chat.

## Approved scope and constraints

- Multiple sites managed by one administrator/team; multitenancy is deferred.
- Start with an explicit local catalog backend and public Genro Storage payload access. Asqueel/PostgreSQL is a future catalog backend, not an import, installation or startup requirement.
- Templates use Gramlot or HtmlBuilder and declare named Data blocks. Each value has a canonical HTML or Markdown source; required and optional declarations are preserved. The template controls layout.
- Generic/site templates, CSS/JS and media; customization creates an independent site copy. Dependency references remain explicit, not live inheritance.
- Shared drafts with expected-generation conflict checks, immutable revisions and idempotent commands. Each language can be published when ready in the later publication macro.
- Direct publication by an authorized publisher, with review configurable per site. This macro stores the relevant declarations and readiness results; actual approval transitions and publication are later consumers.
- The complete product remains the scope of the roadmap, not a reduced two-endpoint product. This macro deliberately has no admin UI or public renderer.
- Initial execution profile: one catalog writer/coordinator on a qualified local filesystem, one host. API requests may be concurrent; all mutations pass through the coordinator. A second process cannot own the same catalog simultaneously. No NFS, object-store-as-filesystem or distributed-writer claims.
- The catalog coordinator must serialize commits from concurrent synchronous request handlers without assuming that Kajenn runs every handler on the same thread.
- Catalog generations, operation receipts and audit/event references share one commit boundary. Use versioned manifests and immutable history; readers pin one committed generation. Do not independently mutate a head file, receipt file and event file and call the sequence atomic.
- Catalog filesystem primitives belong to this explicit backend. Payloads use public Genro Storage APIs; no private backend access, fake adapters or assumed atomic `StorageNode.move_to`.
- Read-back and checksums are necessary but do not prove power-loss durability. Qualify the actual local flush/replace/exclusive-create path; state the tested platform and limitations. Missing required framework primitives are a concrete upstream dependency, not permission to silently weaken the contract.
- Python package/distribution names: `kajenn_public_site` / `kajenn-public-site`. Use a `src/` package, Python >=3.11, Hatchling packaging, pytest and Ruff consistent with inspected family projects. Initial runtime dependencies are Kajenn and Genro Storage; do not install Gramlot or database drivers just to complete this macro. Select compatible artifact versions from actual qualification, never infer a released package from a dirty checkout. Additional dependencies require the interactive phase gate.
- Local catalog and payload formats are versioned. Prefer JSON manifests with explicit schema version, deterministic encoding and SHA-256 over exact stored bytes; preserve raw HTML/Markdown/CSS/JS bytes separately. Do not invent a general ORM, query language, plugin loader or unused persistence helpers.
- Treat configured roots as private application-owned directories. Logical names/IDs do not become unrestricted filesystem paths; test traversal and symlink containment for writable/readable resource access. No anonymous admin routes or trust in role fields supplied by a client.
- Existing product decisions live in `docs/01-visione.md` through `docs/08-decisioni.md`. The original prompt is historical: subsequent filesystem-first, named-block and workflow decisions take precedence where it differs.
- Retention durations, backup schedules/RPO/RTO, CDN policy, automatic destructive collection and Asqueel integration are deferred. Do not adopt the unapproved 90-day suggestion.
