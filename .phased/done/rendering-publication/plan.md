## Approved decisions and execution boundaries

- Three serial interactive phases, in this chat, with contract skeletons authored now. Phase implementation starts only on the user's execution request. This plan authorizes no deployment, package release, sibling edits or automatic later macro execution.
- Python templates and JavaScript assets are trusted administrator/team code, including code prepared by an authorized LLM. Build work executes outside the request handler in a separate process, with a minimal environment, explicit immutable inputs, bounded output and timeout. This is fault containment, not a security sandbox against hostile code running as the same OS user. Do not pass management tokens, catalog handles or unrelated site data to the worker.
- Worker dependencies and renderer/profile versions are recorded in build inputs. Qualify real installed artifacts in an isolated environment, outside upstream source trees, then pin the verified rendering set. Keep existing Kajenn 0.5.0 runtime unless qualification demonstrates a concrete incompatibility; report an upstream gap instead of silently using dirty sibling checkouts.
- New rendering-profile dependencies approved for qualification: Gramlot, direct Genro Builders/Bag imports as required, `markdown-it-py` and `nh3`. The optional profile must not make Gramlot mandatory for existing editorial scenarios. No invented fallback renderer or application-local fork of an upstream capability.
- Templates declare named HTML/Markdown blocks. Markdown allows embedded HTML, tables, strikethrough and fenced code; parse first, then filter resulting HTML with the same versioned editorial profile as native HTML blocks. Preserve headings, lists, links, images, tables, code, class names and explicitly allowed basic formatting styles. Exclude scripts, event handlers, executable URL schemes and arbitrary embedded documents from content blocks; trusted template CSS/JS remain separate exact resources. Record removals as diagnostics, and fail readiness if a required block loses all meaningful content. Do not claim every future Jodit feature is already supported.
- Plain text and prepared HTML have distinct application values. Only the preparation adapter may mark HTML for raw insertion; ordinary strings, including literal `::HTML` suffixes, must not gain raw privileges. Qualify both renderer paths with hostile-looking text and attributes. Unsupported browser-only bindings affecting essential content must produce diagnostics, not a silently incomplete public page.
- Explicit dependencies only: snapshot template/CSS/JS/media closure before rendering. No automatic network downloads or runtime selection of current resources. Define build Data with site/page/language metadata, prepared named blocks and resolved exact resource URLs; the adapter translates this versioned application schema to each engine's public Bag API. Do not expose a catalog or service object to template code.
- All page URLs contain a language prefix: `/it/chi-siamo/`, `/en/about/`. The site root redirects to its configured primary language landing page. Per-variant route paths are versioned, editable and independent of IDs. Normalize Unicode consistently, use canonical directory-style paths, reserve technical paths and reject traversal, ambiguous encoding and normalized collisions before sealing. Require a selected landing page for the primary language before activation; never redirect to an absent variant.
- Versioned publication settings provide primary language, canonical public origin and channel identity; route metadata provides localized path, title and description. Origins/host bindings are explicitly administrator-configured, never derived from an untrusted request Host header. A content-reference resolver uses stable IDs and the frozen candidate map; unresolved internal links/media produce named diagnostics. Earlier plain text remains valid without migration.
- Canonical, reciprocal hreflang and sitemap derive from one frozen route map and include only selected variants. Do not emit x-default by default. Preserve editorial modification information; do not claim build time is modification time. Initial releases contain the pages/resources represented today; menus, taxonomy, courses, scheduling and richer content types remain Macro 4.
- Preview is an expiring, revocable bearer grant for exactly one candidate/build on a separate origin, without administration credentials. The link can be opened without an administration account. Exchange bootstrap credentials for restricted browser access where needed; exclude secrets from page markup, manifests, logs and shared cache keys. Check grant scope/expiry/revocation for every page and asset request, including HEAD. Revocation works after startup and after restart; possession of a resource hash is never access permission. Use no-store, noindex and a restrictive referrer policy. Preview links remain within the preview context while canonical metadata describes the intended public destination.
- Use a durable local build job and one bounded worker slot initially; no Redis, SQL or unqualified Kajenn task spool. The coordinator owns catalog writes. Workers receive immutable inputs and return output for parent validation; they do not open another catalog writer. Recovery marks interrupted attempts explicitly; retry uses the same frozen candidate and cannot let a late attempt overwrite the chosen result. Timeout/output limits and preview lifetime are explicit configurable positive values qualified in examples/tests, not a production capacity or retention SLA.
- Complete rebuild is the reference behavior; no incremental-build promise in this macro. Seal an artifact manifest only after every output is present and verified. An unsuccessful build is inspectable but never ready or publicly served. Preview/public rendering share the same preparation pipeline and candidate; origin differences are explicit and byte identity is not promised.
- Activation and rollback update one channel pointer conditionally and atomically with their receipt/audit/event records. Recheck current scope grants, complete artifact closure, channel/configuration compatibility and review policy under the coordinator. Sites with review_required=true cannot publish until a supported approval flow exists; return a structured policy error. Publication remains direct for authorized publishers when review is disabled.
- Each public request pins one release before resolving its route and bytes. Use release-qualified immutable asset URLs so an activation cannot mix a page with new assets. Only published retained releases are eligible for public asset access; candidates and drafts stay private. Retention/GC and emergency revocation policy remain later work; no automatic deletion. HTML resolves the authoritative pointer per request; do not promise CDN-wide atomicity.
- Existing read/write/use/create_site grants remain intact. Add explicit build, preview-grant and publish permissions in trusted deployment policy; neither ordinary write nor use implicitly authorizes publication or granting preview access. Keep principal injection, idempotency and structured error envelopes equivalent across REST/MCP. New job/artifact records must not accidentally leak through existing editorial record listings or be decoded as source text.
